# 讓 OCS「用 00059094 搜尋使用者」可回傳對應帳號的 LDAP 設定說明

## 1. 問題與程式行為摘要

- **7. Get User(SMG_ARC304) UID**：`search=SMG_ARC304` 有結果 → 表示 LDAP 的「使用者識別」或「顯示名稱」中有 `SMG_ARC304`。
- **7.1. Get User(00059094) UID**：`search=Hui%20Yu%20Huang` 有結果 → 表示搜尋是對「顯示名稱」比對，可找到 Hui Yu Huang-黃慧瑜。
- **7.2. Get User(00059094) UID**：`search=00059094` 回傳空值 → 表示目前 LDAP 搜尋**沒有**用存放 `00059094` 的屬性來查詢。

`ad_users_list.csv` 中 00059094 對應「Hui Yu Huang-黃慧瑜」，亦即 **00059094 是 AD 的「帳號」欄位**，在 AD/LDAP 裡通常是 `employeeID` 或 `sAMAccountName` 等屬性。

---

## 2. 程式碼中的搜尋流程（簡述）

- OCS：`/ocs/v1.php/cloud/users?search=...` 會呼叫 `IUserManager::search($search, ...)`。
- 每個 backend 實作 `getUsers($search, ...)`；**user_ldap** 在 `User_LDAP::getUsers()` 裡用 `Access::getFilterPartForUserSearch($search)` 組 LDAP filter。
- `getFilterPartForUserSearch()` 的邏輯（`Access.php`）：
  - 若有設定 **ldapAttributesForUserSearch**（「用於使用者搜尋的屬性」）：搜尋字串會對這些屬性做 **OR** 比對。
  - 若**未設定**：只會用 **ldapUserDisplayName**（顯示名稱對應的屬性）做為 fallback。

因此目前行為是：只會用「顯示名稱」在搜，所以 `Hui Yu Huang` 找得到、`00059094` 找不到。要讓 `00059094` 也能被搜到，就必須把「存放 00059094 的 LDAP 屬性」加入「用於使用者搜尋的屬性」。

---

## 3. 解決方式：設定「用於使用者搜尋的屬性」

目標：讓 `GET /ocs/v1.php/cloud/users?search=00059094` 能命中「Hui Yu Huang-黃慧瑜」這名使用者。

做法：在 Nextcloud 的 **LDAP 設定** 裡，把 **「Attributes for user search」**（對應設定鍵 `ldap_attributes_for_user_search`）加入存放 00059094 的 AD 屬性。

### 3.1 先確認 AD 裡 00059094 在哪個屬性

常見可能：

- **employeeID**：很多企業用於工號。
- **sAMAccountName**：若 00059094 是 Windows 登入帳號。

請在 AD 上確認該使用者的 00059094 實際對應哪個屬性（例如用「Active Directory 使用者及電腦」→ 該使用者 → 屬性，或用 `ldapsearch` 查該使用者的 object）。

### 3.2 在 Nextcloud 設定「用於使用者搜尋的屬性」

**方式 A：圖形介面**

1. 以管理員登入 Nextcloud。
2. **設定** → **管理** → **使用者與群組**（或 **LDAP / 企業版目錄**）。
3. 點選你的 LDAP 設定（例如「LDAP」或對應的 server）。
4. 切到 **進階**（Advanced）分頁。
5. 找到 **「Attributes for user search」**（或用戶搜尋屬性 / 用於使用者搜尋的屬性）。
6. 在欄位中填入要參與搜尋的屬性，**多個屬性用分號 `;` 分隔**。  
   - 若 00059094 在 **employeeID**，可設為例如：  
     `displayname;employeeID`  
     （保留 displayname 可繼續用姓名搜；名稱依你目前「顯示名稱」實際對應的屬性調整，若已是 `displayName` 就寫 `displayName`。）
   - 若 00059094 在 **sAMAccountName**，可設為例如：  
     `displayname;sAMAccountName`
7. 儲存後可執行一次「清空快取並重新載入」或等快取過期，再測 `search=00059094`。

**方式 B：用 occ 指令設定**

Nextcloud 內建 `ldap:set-config`，可直接改 LDAP 設定。

1. **查出現有 LDAP 設定 ID**（通常為 `s01` 或 `s1`）：
   ```bash
   php occ ldap:show-config
   ```
   輸出表格第一欄為設定名稱、第二欄為該 config 的 ID；或指定 ID 查看：
   ```bash
   php occ ldap:show-config s01
   ```

2. **設定「用於使用者搜尋的屬性」**（多個屬性用分號 `;` 分隔）：
   ```bash
   php occ ldap:set-config <configID> ldapAttributesForUserSearch "displayName;employeeID"
   ```
   若 00059094 在 AD 的屬性是 `sAMAccountName`，則：
   ```bash
   php occ ldap:set-config <configID> ldapAttributesForUserSearch "displayName;sAMAccountName"
   ```
   請將 `<configID>` 換成上一步看到的 ID（例如 `s01`）。

3. **清快取**（可選，讓變更立即生效）：
   ```bash
   php occ ldap:set-config <configID> ldapCacheTTL 0
   ```
   再視需要改回原本 TTL（例如 600）或等下次自動過期。

### 3.3 設定值範例（依你 AD 屬性擇一或都加）

若顯示名稱對應 `displayName`、且 00059094 在 employeeID：

```text
displayName;employeeID
```

若 00059094 在 sAMAccountName：

```text
displayName;sAMAccountName
```

若兩個屬性都要能搜（工號與登入帳號都可搜）：

```text
displayName;employeeID;sAMAccountName
```

（屬性名稱請依你 AD schema 實際名稱填寫，大小寫須與 LDAP 回傳一致，通常 AD 用 `employeeID`、`sAMAccountName`。）

## 4. ldapUserFilter：使用者清單範圍（真人 + 部門帳號）

**ldapUserFilter** 決定「哪些 LDAP 物件會被 Nextcloud 當成使用者」；只有符合此條件的物件才會被同步、出現在使用者清單。

### 4.1 目前常見設定與用意

```text
(&(objectCategory=person)(objectClass=user)(sAMAccountName=*))
```

| 片段 | 意義 |
|------|------|
| `&(...)` | 所有條件都要符合（AND） |
| `objectCategory=person` | 物件類別為「人」 |
| `objectClass=user` | 物件類別為 user（AD 使用者） |
| `sAMAccountName=*` | 具登入帳號（排除未啟用/電腦帳號等） |

即：只帶入「真人使用者且已有登入帳號」的 AD 帳號。

### 4.2 擴充為「真人使用者 + 部門帳號」

若要同時帶入**部門帳號**（例如依群組或帳號命名規則），可用 **OR** 合併條件。

**方式 A：部門帳號依「群組」**（請改為貴公司群組 DN）

```text
(|(&(objectCategory=person)(objectClass=user)(sAMAccountName=*))(memberOf=CN=部門帳號群組,OU=Groups,DC=UMC,DC=com))
```

**方式 B：部門帳號依「sAMAccountName 前綴」**（例如 `DEPT_`、`SMG_`）

```text
(|(&(objectCategory=person)(objectClass=user)(sAMAccountName=*))(sAMAccountName=DEPT_*))
```

**occ 指令範例**（請將 `<configID>` 換成實際 ID，filter 內雙引號需跳脫或外層用單引號）：

```bash
# 真人 + 部門群組
php occ ldap:set-config <configID> ldapUserFilter '(|(&(objectCategory=person)(objectClass=user)(sAMAccountName=*))(memberOf=CN=DeptAccounts,OU=Groups,DC=UMC,DC=com))'

# 真人 + 前綴 DEPT_
php occ ldap:set-config <configID> ldapUserFilter '(|(&(objectCategory=person)(objectClass=user)(sAMAccountName=*))(sAMAccountName=DEPT_*))'
```

與 **ref/ad_users_list.py** 的篩選邏輯對齊時，可依該腳本中的 `DEPT_GROUP_DN` / `DEPT_SAM_PREFIX` 設定，使用同一段 filter 字串設為 ldapUserFilter。

## 5. ldapUserDisplayName2：畫面顯示名稱呈現帳號

Nextcloud 畫面的「顯示名稱」由兩個 LDAP 屬性組成：

- **ldapUserDisplayName**（主要）：目前多為 `displayname` → 顯示「Hui Yu Huang-黃慧瑜」。
- **ldapUserDisplayName2**（次要）：若設定，程式會組合成 **「主要 (次要)」**，例如 **姓名 (帳號)**。

### 5.1 顯示為「姓名 (sAMAccountName)」

讓顯示名稱同時看到中文姓名與帳號（如 00059094、SMG_ARC304）：

- **ldapUserDisplayName**：維持 `displayname`（或 `displayName`）。
- **ldapUserDisplayName2**：設為 `sAMAccountName`。

**occ 指令：**

```bash
php occ ldap:set-config <configID> ldapUserDisplayName2 sAMAccountName
```

設定後需讓 LDAP 重新同步顯示名稱（清快取或等同步），畫面即會顯示如「Hui Yu Huang-黃慧瑜 (00059094)」。

### 5.2 僅顯示 sAMAccountName（不顯示姓名）

若希望畫面只顯示帳號：

```bash
php occ ldap:set-config <configID> ldapUserDisplayName sAMAccountName
php occ ldap:set-config <configID> ldapUserDisplayName2 ""
```

## 6. 設定後驗證

再次呼叫：

```http
GET /ocs/v1.php/cloud/users?search=00059094&format=json
```

預期：回傳中會出現對應「Hui Yu Huang-黃慧瑜」的那筆使用者（其 `id` 為 Nextcloud 帳號名稱 / UID）。  
若仍為空，請檢查：

- LDAP 快取是否已更新（清空 LDAP 快取後再測）。
- AD 該使用者物件是否確實有 00059094 在設定的屬性裡。
- 「Attributes for user search」是否儲存成功（重新打開進階分頁確認）。

## 7. 總結

| 項目 | 說明 |
|------|------|
| 原因 | OCS 使用者搜尋只用「顯示名稱」或你設定的「用於使用者搜尋的屬性」；未包含 00059094 所在屬性，故 `search=00059094` 無結果。 |
| 做法 | 在 LDAP 的 **Attributes for user search**（ldapAttributesForUserSearch）中加入存放 00059094 的屬性（如 `sAMAccountName`），多個屬性以 `;` 分隔。 |
| ldapUserFilter | 決定哪些 LDAP 物件算「使用者」。僅真人：`(&(objectCategory=person)(objectClass=user)(sAMAccountName=*))`；要含部門帳號時用 OR 合併條件（見 §4.2），可與 **ref/ad_users_list.py** 的 filter 對齊。 |
| ldapUserDisplayName2 | 設為 `sAMAccountName` 可讓畫面顯示「姓名 (帳號)」；僅要帳號則把 ldapUserDisplayName 改為 `sAMAccountName`、ldapUserDisplayName2 清空。 |
| 驗證 | 以 `GET /ocs/v1.php/cloud/users?search=00059094` 測試，應可回傳對應帳號。 |

以上設定僅影響「搜尋時用哪些 LDAP 屬性比對」與「顯示名稱來源」，不會改變登入用的帳號或密碼驗證邏輯。
